## The issue

While working on Quiver's Teams attachment intake, I found that the OpenClaw Teams adapter did not respect the channel's configured inbound media limit. This mattered for a workflow that needs to receive source documents without applying the wrong size boundary.

## The contribution

I traced the configuration path and made the adapter prefer the Teams-specific limit. If Teams has no override, it falls back to the agent default. I added regression tests for both cases in [upstream commit `c1243671`](https://github.com/openclaw/openclaw/commit/c12436718ead1aaae00c038d76f502e307853455).

This is a focused contribution to OpenClaw, not authorship of the upstream runtime. Quiver uses OpenClaw; the reusable fix belongs in the runtime itself.
